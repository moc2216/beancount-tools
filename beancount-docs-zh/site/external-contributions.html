Beancount 的外部贡献

Martin Blais - 更新于：2024 年 6 月

http://furius.ca/beancount/doc/contrib

指向由其他人编写的、基于 Beancount 和/或 Ledgerhub 构建或与之相关的代码的链接。

索引

本文档仅包含那些曾被讨论过或已向邮件列表发送过公告的包。你可以在公共索引上找到其他包：

  • PyPI：你可以在 PyPI 上找到许多其他与 Beancount 相关的项目。

  • GitHub：截至 2020 年 9 月，搜索 "beancount" 会显示 318 个项目。

  • awesome-beancount.com：一个精选的 Beancount 资源列表，Beancount 是一个基于命令行、使用纯文本文件的双式记账系统。

书籍与文章

使用 Python 管理个人财务（Siddhant Goel）：一本关于纯文本会计和 Beancount 的 2020 年出版的书籍。

五分钟账本更新（RedStreet）：一系列文章，展示了如何自动化从机构（银行、信用卡、经纪商等）下载数据，以便在五分钟以内完成账本更新。邮件列表讨论串。

使用 Beancount 进行税务亏损收割（RedStreet）：一篇从美国视角探讨 TLH 的文章，涵盖了相关要求、wash sale 的细微差别以及安全的卖出/买入日期，并与 robo-advisors 进行了比较。（相关：fava_investor TLH 模块，适用于 fava 和纯 Beancount 命令行版本）。

共同基金 NAV 的缩放估算（RedStreet）：问题在于：共同基金的 NAV（至少在美国）每天仅在收盘时更新一次。当需要在交易窗口仍开放时做出财务决策（例如：进行税务亏损收割时），而当日收盘 NAV 尚未可用时，有时对 NAV 进行粗略估算会很有用，尤其是在市场波动剧烈的日子。

从 Fidelity 抓取交易历史的快捷方式（David Avraamides）：我撰写了一篇描述，说明如何使用 Shortcut 从 Fidelity 网站抓取交易历史，通过 Python 脚本将其转换为 Beancount 的账本格式，然后将其保存到剪贴板，以便粘贴到账本文件中。

懒人的 Beancount（Vasily M）/ Evernight/lazy-beancount：一份关于如何开始（并继续）使用开源 Beancount 会计系统追踪个人财务的观点鲜明的指南。它附带了一些代码。该指南的主要目标是为您提供一种方式，使用纯文本会计逐步且增量地开始管理自己的财务。同时也包含并配置了各种有用的工具。

平衡之道 — https://academy.beanhub.io/（Fang-Pen Lin）：使用可视化和图表解释复式记账法。

Beancount 中的多周期 hledger 风格报告：透视表 | Altynbek Isabekov：一篇展示如何生成账户余额透视表摘要的文章，例如按年份汇总，并附有相关代码 (github)。

我信任的一个数字：多币种家庭的纯文本会计 - Lalit Maganti - 一篇记录 DEB 各种使用示例的文章。

交互式 beanquery 手册（Chary Ev2geny）：涵盖了 beanquery 的最新功能，包含许多使用实际账本的实例，具有自文档化特性：所有查询输出都是作为 notebook 执行的一部分通过运行 beanquery 计算得出的；具有交互性：当作为 marimo notebook 运行时，读者可以通过更改默认账本和/或查询进行实验，输出会自动更新。

Beancount 或黑客的会计（Cyril Deguet）

插件

split_transactions：Johann Klähn 编写了一个插件，可以将单个 transaction 拆分到多个针对 limbo account 的 posting 中，类似于折旧处理。

zerosum：Red S 编写了一个插件，用于匹配那些合在一起总和应为零的 transaction，并将它们移动到一个单独的 account 中。

effective_dates：Red S 编写了一个插件，用于将 transaction 的不同部分 booking 到不同的日期。

beancount-plugins：Dave Stephens 创建了一个仓库，用于分享他编写的与折旧相关的各种插件。

beancount-plugins-zack：Stefano Zacchiroli 创建了这个仓库来分享他的插件。包含 directive 排序等功能。

beancount-oneliner：Akuukis 创建了一个插件，用于在一行中写入 entry（PyPi）。

beancount-interpolate：Akuukis 为 Beancount 创建了用于 transaction interpolation 的插件（recur, split, depr, spread）（PyPi）。

metadata-spray：通过正则表达式跨 entries 添加元数据，而不是使用显式的 entries（由 Vivek Gani 编写）。

Akuukis/beancount_share：一个 Beancount 插件，用于在一个 ledger 内将费用在多个合伙人之间分摊。这个插件功能非常强大，很可能可以满足你所有的分摊需求。

w1ndy/beancount_balexpr（Di Weng）：一个提供“balance expressions”的插件，可作为 Custom directive 针对 Beancount entries 运行。参见此线程。

autobean.narration（Archimedes Smith）：允许通过从行内注释填充 per-posting narration 元数据，以简洁的方式为每个 posting 添加注释。

autobean.sorted：检查每个文件中的 transaction 是否按非降序排列。通过警告那些未按日期非降序排列的 directive，帮助识别位置错误或日期错误的 directive。

hoostus/beancount-asset-transfer-plugin：一个插件，用于在两个 Beancount account 之间自动生成实物转移，同时保留 cost basis 和获取日期。

PhracturedBlue/fava-portfolio-summary（Phractured Blue）：一个 Fava 插件，用于显示带有收益率的投资组合摘要。

rename_accounts：Red S 编写的用于重命名 account 的插件。例如：将“Expenses:Taxes”重命名为“Income:Taxes”有助于费用分析。更多详情在此。

Long_short capital gains classifier：Red S 编写的插件，根据资产持有期限将资本利得分类为长期和短期，并根据价值分类为收益和损失。

Autoclose_tree：当关闭一个 account 时，自动关闭该 account 的所有后代。

Evernight/beancount-valuation（Vasily M）：一个 Beancount 插件，用于跟踪不透明基金的总价值。你可以使用它代替 balance assertion 来断言 account 的总价值。如果 account 的当前价值不同，它将改为调整由插件用于技术目的创建的底层合成商品的 price。

Evernight/beancount-plugin-tax-uk（Vasily M）：一个为 Beancount 生成英国资本利得、股息和其他 investment income 税务 report 的插件。

beancount_reds_plugins/…/box_accrual（Redstreet）：自动按比例将合成贷款（box spread）的资本损失分摊到各个日历年，创建用于报告的准确年度应计 entry。

scanta2/ESPPresso（Stefano Mihai Canta）：一个用于计算 ESPP 处置普通收入的 Beancount 插件。

工具

alfred-beancount (Yue Wu)：macOS 工具 “Alfred” 的插件，用于快速在 Beancount 文件中录入 transaction。支持完整的 account 名称和收款方匹配。

bean-add (Simon Volpert)：Beancount transaction 录入助手。

hoostus/fincen_114 (Justus Pendleton)：FBAR / FinCEN 114 report 生成器。

ghislainbourgeois/beancount_portfolio_allocation (Ghislain Bourgeois)：一种快速计算不同投资组合中资产配置的方法。

hoostus/portfolio-returns (Justus Pendleton)：投资组合回报率计算器

costflow/syntax (Leplay Li)：一款允许用户从常用即时通讯应用中保存纯文本记账的产品。一种将单行消息转换为 beancount/*ledger 格式的语法。

process control chart (Justus Pendleton)：相对于投资组合规模的支出。讨论帖。

Pinto (Sean Leavey)：Beancount 的增强型命令行界面。支持在 ledger 文件中自动插入 transaction。

PhracturedBlue/fava-encrypt：一种基于 docker 的解决方案，用于在保持 Fava 在线的同时，对静态存储的 beancount 数据进行加密。请参阅此讨论帖以了解背景。

kubauk/beancount-import-gmail：beancount-import-gmail 使用 gmail API 和 OAuth 登录您的邮箱并下载订单详情，然后用于增强您的 transaction 以便于分类。

sulemankm/budget_report：一个非常简单的命令行预算跟踪工具，用于 beancount ledger 文件。

fdavies93/minibudget (Frank Davies)：MiniBudget 是一个旨在使用纯文本格式实现个人和小型企业预算管理的工具。它受 beancount 和 plainbudget 的启发。

dyumnin/dyu_accounting：一套会计配置，用于自动化生成各种财务报表，以符合印度政府的规定。

Gains Minimizer (RedStreet)：自动确定要出售的 lot 以最小化资本利得税。在线示例。

beanahead (Marcus Read)：增加了包含未来 transaction 的功能（自动生成定期 transaction，提供临时预期 transaction，预期 transaction 与导入的 transaction 进行对账；所有功能均可通过 cli 访问）。

autobean-format (Archimedes Smith)：又一个 beancount 格式化程序，由早期项目 autobean-refactor 提供支持，autobean-refactor 是一个用于解析和以编程方式操作 beancount 文件的库。基于正确的解析器，使其能够格式化 ledger 的每个角落，包括算术表达式。

akirak/flymake-bean-check (Akira Komamura)：Emacs 的 flymake 支持。

bean-download (Red Street)：随 beancount-reds-importers 一起提供的下载器，您可以配置它运行任意命令来下载您的 account 对账单。它现在有一个新功能：needs-update 子命令。

gerdemb/beanpost (Ben Gerdemann)：Beanpost 由一个 PostgreSQL 架构和导入/导出命令组成，允许您在 beancount 文件和 PostgreSQL 数据库之间传输数据。Beancount 的许多功能是使用自定义 PostgreSQL 函数实现的，允许进行复杂的查询和数据操作。此设置提供了一个灵活的后端，可以与 web 应用程序或 report 系统等其他工具集成

LaunchPlatform/beanhub-cli (Fang-Pen Lin)：BeanHub 或 Beancount 用户的命令行工具。

zacchiro/beangrep：Beangrep 是 Beancount 纯文本会计系统的类 grep 过滤器。

Ev2geny/evbeantools：该工具使得在汇率变动以及资金从一种商品转移到另一种商品（包括基于 cost 和非基于 cost 的跟踪）的多币种/多商品 ledger 情况下，能够解释任意两个日期之间净资产的变化。这是通过创建一个转换/等效 ledger 来实现的，可以使用 beanquery 在其上进行进一步分析。

d-k-c/bean-acb (Damien Riegel)：一个帮助跟踪财产调整后成本基础（ACB）的脚本。该规则在加拿大用于计算处置财产时必须申报的资本利得。

tesujimath/bean-sort (Simon Guest)：bean-sort 是一个用于 Beancount 文件的简单排序实用程序。它之所以简单，是因为它不尝试解析文件，只是按日期字段进行分割。

Beanquick (https://twobitsware.com/beanquick)：一款 macOS 应用程序，提供三种录入 transaction 的方式，从引导式表单到快速语法。

paulsc/fava-edit-replay (Paul S)：此扩展允许你一次性对多个 Beancount transaction 应用批量编辑，将编辑操作（搜索过滤器与 diff 的组合）保存为“replays”，以便稍后应用；可按 account、时间段或自定义过滤器筛选 transaction，并根据最近修改的 transaction 建议过滤器。

alensiljak/ledger2bql (Alen Šiljak)：为 Beancount 提供 ledger 风格的查询。

bean-inquiry (Oscar & Ale)：运行带参数的查询。

slimslickner/beanschedule (Tim Tichner)：beanschedule 提供两个主要功能：一个用于预测计划 transaction 的 plugin，以及一个用于增强导入 transaction 的 hook。每个 schedule 都定义为一个 yaml 文件，包含匹配逻辑、重复规则和预期的 posting。目前，唯一的“动态” posting 是贷款摊销，其中会包含 Interest 和 Principal 等 account；基本的匹配仅是一个 cost 范围。

romamo/beancount-cli (Roman Medvedev)：这是一个基于 Beancount v3 和 Pydantic 构建的现代 CLI。除了标准的 ledger 任务外，我一直致力于使其“agent-friendly”——即通过描述性的帮助字符串和内置的 JSON schema 发现机制，使其能与 AI 助手和自动化工作流良好配合。

AI 工具

MCP 服务器

vanto/beanquery-mcp（Tammo van Lessen）：一个实验性的 MCP 服务器，用于演示如何结合 Claude 处理 BQL 的 beanquery。截图。（这是一个概念验证（PoC），您应谨慎选择希望与哪个 LLM 共享的数据。）

StdioA/beancount-mcp（David Dai）：一个 Beancount MCP 服务器，可以执行 beancount 查询，并向账本提交 (a) transaction。

替代实现

yagebu/uromyces (Jakob Schnitzer)：uromyces 是 Beancount 部分功能的 Rust 玩具级重新实现。

themoritz/turbobean (Moritz Drexl)：Beancount 的 Zig 语言替代实现。这是一个从零开始实现的 Beancount，速度快且不依赖 Python 生态系统。

tesujimath/limabean (Simon Guest)：这是一个使用 Rust、Clojure 和 Lima 解析器实现的 Beancount 新版本。

替代解析器

Bison（parser generator）

Beancount v2 解析器使用 GNU flex + GNU bison（以实现最大可移植性）。

Beancount v3 解析器使用 RE/flex + GNU bison（以支持 Unicode 和 C++）。

使用 Antlr

jord1e/jbeancount（Jordie Biemold）/ 使用 Antlr：一个用于 Beancount 输入语法的替代解析器，以 Java 实现（使用 Antlr4 解析器生成器）。这允许从 JVM 语言访问解析后的 Beancount 数据——而不受插件影响。详情请参阅此帖子。

使用 Tree-sitter

polarmutex/tree-sitter-beancount（Bryan Ryall）：一个用于 Beancount 语法的 tree-sitter 解析器。

https://github.com/dnicolodi/tree-sitter-beancount（Daniele Nicolodi）：另一个基于 tree-sitter 的 Beancount 语法解析器。

Rust 实现

jcornaz/beancount-parser（Jonathan Cornaz）：一个用于 Rust 的 beancount 文件解析库。使用 nom。

beancount_parser_lima（Simon Guest）：一个 Rust 中的 Beancount 零拷贝解析器。它旨在完整实现 Beancount 文件格式，除了那些已弃用的部分以及此处记录的其他功能（该列表可能并不全面）。使用 Logos、Chumsky 和 Ariadne。

Emacs Lisp（编辑器脚本）

trs-80/beancount-txn-elisp/：beancount-txn-elisp：一个用 Emacs Lisp 实现的库，用于读取/解析和写入/插入单个 Beancount transaction。

导入器

reds importers：针对多家美国机构及多种文件类型的简单导入器和工具。它通过提供维护良好的通用库（涵盖银行、信用卡、投资机构以及各种文件类型），强调编写自定义导入器的便捷性，从而最大限度地减少你需要编写的特定机构代码。这是 五分钟账本更新 中所表达原则的参考实现。欢迎贡献。由 RedStreet 开发。

plaid2text：一个从 Plaid 获取数据的导入器，它将 transaction 存储到 Mongo DB 中，并能够将其渲染为 Beancount 语法。由 Micah Duke 开发。

jbms/beancount-import：一个用于从外部数据源半自动导入 transaction 的工具，支持将导入的 transaction 彼此之间以及与 beancount 日志中现有 transaction 进行合并和对账。其 UI 基于 Web。(公告，旧版本链接)。由 Jeremy Maitin-Shepard 开发。

awesome-beancount：针对中国银行的导入器集合 + 技巧与窍门。由 Zhuoyun Wei 开发。

beansoup：Filippo Tampieri 在此项目中分享了他的一些 Beancount 导入器和自动补全器。

montaropdf/beancount-importers：一个用于从工时表格式中提取加班费和休假以向客户开具发票的导入器。

siddhantgoel/beancount-dkb (Siddhant Goel)：用于 DKB CSV 文件的导入器。

prabusw/beancount-importer-zerodha：用于印度券商 Zerodha 的导入器。

prabusw/beancount-importers-india：用于部分印度银行和券商的导入器（已更新以使用 beangulp + v3）。

swapi/beancount-utils：另一个用于 Zerodha 的导入器。

Dr-Nuke/drnuke-bean (Dr Nuke)：一个基于 flex query（类似 API）的 IBKR 导入器，以及一个用于瑞士邮政银行（Swiss PostFinance）的导入器。

Beanborg (Luciano Fiandesio)：Beanborg 自动从外部 CSV 文件导入财务 transaction 到 Beancount 记账系统中。

szabootibor/beancount-degiro (PyPI)：用于荷兰券商 Degiro 交易账户的导入器。

siddhantgoel/beancount-ing-diba (PyPI)：ING 账户导入器（荷兰）。

PaulsTek/csv2bean：一个使用 Google Sheets 预处理 CSV 文件的简单 Go 应用程序。

ericaltendorf/magicbeans (Eric Altendorf)：用于加密货币数据的 Beancount 导入器。提供详细的 lot 跟踪以及加密货币资产的资本利得/损失 report。"我编写它是因为我对现有商业加密货币税务 report 服务的准确性或透明度不满意。"

OSadovy/uabean (Oleksii Sadovyi)：一套针对乌克兰流行银行及其他机构的 Beancount 导入器和脚本。

fdavies93/seneca (Frank Davies)：用于 Wise 的导入器。支持多币种转账。

LaunchPlatform/beanhub-import：带有 UI 的新 Beancount 导入器。

rlan/beancount-multitool (Rick Lan)：Beancount Multitool 是一个命令行界面 (CLI) 工具，用于将金融机构的财务数据转换为 Beancount 文件（支持：JA Bank ＪＡネットバンク, Rakuten Card 楽天カード, Rakuten Bank 楽天銀行, SBI Shinsei Bank 新生银行）。相关文章：https://www.linkedin.com/feed/update/urn:li:activity:7198125470662500352/

LaunchPlatform/beanhub-import (Fang-Pen Lin)：Beanhub-import 是一个简单、声明式、智能且易于使用的库，用于从 beanhub-extract 导入提取的 transaction。它基于预定义规则生成 Beancount transaction。

Sieboldianus/beancount-hibiscus-importer：Hibiscus 是德国广泛使用的开源软件。它支持使用 HBCI 或 FinTS 标准从银行获取 transaction，并（通过插件）通过网页抓取（信用卡）或 API（例如 Paypal）获取。此 Beancount Hibiscus Importer 提供导入功能，用于从 Hibiscus H2DB（直接或通过 XML-RPC）获取 transaction，并使用 v3 Beangulp 接口将其转换为 Beancount 格式。

flowerbug/bcgt：一个用于生成股票买入、卖出和拆股 Beancount Transaction 的工具。Bcgt 改编自 beangrow 中引用的 export.py 程序，该程序在早期 beancount 版本中可用。

AmmarShaqeel/maybank-importer (Ammar Shaqeel)：用于 Maybank（马来西亚）PDF 对账单的导入器。

AmmarShaqeel/rajhi-importer (Ammar Shaqeel)：用于 Rajhi（沙特阿拉伯）PDF 对账单的导入器。

redstreet/beancount_reds_importers//amazon（Redstreet）：用于处理 Amazon GDPR 数据导出的 Beancount Reds Importers。

tarioch/beancounttools：针对 AwardWallet 的 importer，该服务提供（免费的）API，并集成了约 460 个航空公司、租车、购物及其他领域的忠诚度计划。

https://github.com/tesujimath/limabean-harvest（Simon Guest）：limabean-harvest 是一个新的 Beancount importer，基于与 limabean 相似的原则构建，即混合使用 Rust 和 Clojure。其引人注目的特性包括：以数据而非代码进行配置，从 payee 和 narration 字段推断 secondary accounts，特别是这使得在同一组中导入的两个账户之间的 transaction 配对成为可能。

ledger2beancount：用于将 ledger 文件转换为 beancount 的脚本。由 Stefano Zacchiroli 和 Martin Michlmayr 开发。

下载器

bean-download (RedStreet)：bean-download 是一个用于从支持的机构便捷下载 transaction 的工具。你通过配置机构列表和任意下载命令（通常通过 ofxget）来使用它。它会并行下载所有文件，正确命名它们，并将其放入你选择的目录中，之后你可以从中导入。该工具作为 beancount-reds-importers 的一部分进行安装。请参阅 配套文章。

ofx-summarize (RedStreet)：在构建 importer 时，能够查看你试图导入的 .ofx 或 .qfx 文件的内容会很有帮助。ofx-summarize 命令正是为此而设计的。它随 beancount-reds-importers 一起提供，通常只需调用该命令即可使用。在文件上运行该命令会显示文件中的几笔 transaction。非常有用的是，你可以通过 python 调试器或解释器来探索你的 .ofx 文件。

接口 / Web

fava: Beancount 的 Web 界面（Dominik Aumayr, Jakob Schnitzer）：Beancount 自带一个简单的 Web 前端（“bean-web”），其目的仅作为一个薄壳，用于调用并显示其 report 的 HTML 版本。“Fava” 是一个具有更多且不同功能的替代 Web 应用前端，最初旨在作为一个试验场和概念验证，以探索一种更新、更好的设计来呈现 Beancount 文件的内容。

Fava Classy Portfolio（Vivek Gani）：Classy Portfolio 是 Fava 的一个扩展，Fava 是 Beancount 纯文本会计软件的 Web 界面。该扩展显示不同投资组合（例如 'taxable' 与 'retirement'）的列表，并使用商品上的 'asset-class' 和 'asset-subclass' 元数据标签进行细分。

Fava Investor 项目（RedStreet）：Fava_investor 旨在成为一套针对 Beancount 和 Fava 的综合性 investment 报告、分析工具和工具集。它是一组模块的集合，每个模块提供一个 Fava 插件、一个 Beancount 库以及一个基于 Beancount 的 CLI（命令行界面）。当前模块包括：Visual、按类别划分的树状资产分配、按 account 划分的资产分配、税务亏损收割器、cash drag 分析。

Fava Miler（RedStreet）：航空里程和奖励积分：到期日和价值报告。

Fava Envelope（Brian Ryall）：一个 beancount fava 扩展，为 fava 和 beancount 添加信封预算功能。它作为 Fava 插件和 CLI 开发。

scauligi/refried（Sunjay Cauligi）：一个受 YNAB 启发的 Fava 信封预算插件：所有支出 account 都成为独立的预算类别，预算通过向这些 account 的 transaction 执行，并且该插件自动为所有重新预算的 transaction 应用标签，以便轻松过滤。提供类似 YNAB 的预算和 account 视图。

BeanHub.io：Beancount 内容的 Web 前端。“自从我开始使用 Beancount 以来，我一直梦想让它完全自动化。过去几年，我一直在为此目标构建工具。连接银行并直接从那里获取数据是我想要实现的目标之一。我构建了此功能，并一直在我的账本中测试了一段时间。现在我的 Beancount 账本有 80% 是完全自动化的。我可以打开我的仓库，银行的 transaction 会自动像这样作为新的 commit 出现，而我无需动手。

整个导入系统基于我们的开源 beanhub-import 和 beanhub-extract。导入流程中唯一的专有部分是 Plaid 集成。因此，假设你不信任我，但仍希望自动导入 transaction。只要你连接到 Plaid 并根据从 Plaid 获取的 transaction 编写 CSV 文件，你就应该能够在不使用 BeanHub 服务的情况下拥有相同的自动 transaction 导入系统。”
